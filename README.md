# Bosa Noga — интернет-магазин обуви

Дипломный проект курса «React».

[![CI / Deploy](https://github.com/devlop12x-crypto/bosa-noga-shop/actions/workflows/deploy.yml/badge.svg)](https://github.com/devlop12x-crypto/bosa-noga-shop/actions/workflows/deploy.yml)

**Демо:** https://devlop12x-crypto.github.io/bosa-noga-shop/

## Задача

Работающий интернет-магазин обуви на React по готовой вёрстке и неизменяемому бэкенду: главная с хитами продаж и каталогом, каталог с поиском, страница товара, корзина с оформлением заказа, информационные страницы.

## Нетривиальные решения

- **Магазин отделён от приложения.** Всё, чем магазины отличаются друг от друга, описано в `StorefrontConfig`, а компоненты получают эти данные только через `useStorefront()`. Чтобы сделать из обувного магазина магазин перчаток, достаточно написать новый пакет в `src/brands/` и поменять одну строку в `main.tsx`.
- **Границы слоёв проверяет линтер.** `no-restricted-imports` запрещает импортировать бренд откуда-либо, кроме точки входа, а ядру — импортировать React, Redux и внешние слои.
- **Тесты идут на чужом бренде.** Приложение в тестах работает с конфигурацией магазина перчаток, поэтому любая обувная строка, зашитая в компонент, роняет тест.
- **Товар описан без обувной специфики.** Размеры бэкенда в ядре называются вариантами, остальные строковые поля товара — атрибутами. Какие характеристики показывать и как их подписать, какой лимит количества, как называется колонка «Размер» — всё это задаёт бренд.
- **Правила корзины — чистые функции ядра.** Позиция определяется парой «товар + вариант». Цену фиксирует последнее нажатие «В корзину», количество ограничено лимитом магазина. Redux-слайс — тонкая обёртка над этими функциями.
- **Адаптив под телефон.** Вёрстка диплома рассчитана на десктоп, поэтому на ширине до 576 px меню прячется за «гамбургер», а поиск и корзина остаются рядом с логотипом: DOM один, порядок меняют order-классы Bootstrap. Заголовок баннера масштабируется, а таблица корзины превращается в карточки с подписями из `data-label`, так что «Удалить» не уезжает за экран. На десктопе всё выглядит как в исходной вёрстке.
- **Выбор размера очевиден.** В вёрстке невыбранный размер выглядит как простой текст, поэтому у кнопок размеров есть рамка и отклик на наведение. Над неактивной «В корзину» — подсказка из конфигурации бренда, связанная с кнопкой через `aria-describedby`. После выбора подсказка скрывается, но её место сохраняется, и кнопка не сдвигается под курсором.
- **Смена цены (Profi 1).** Бэкенд цены в заказе не проверяет, поэтому перед отправкой thunk `submitOrder` заново загружает товары из корзины, минуя кэш, и сверяет их с ней (`reconcileCart`). При расхождении заказ не отправляется: в строке видно «было / стало», а новые цены применяются только по кнопке «Принять новые цены». Закончившийся размер или снятый с продажи товар нужно удалить. Та же сверка тихо выполняется при открытии корзины.
- **Телефон и адрес не сохраняются (Profi 2).** Безопасного места для них в браузере нет: localStorage читается любым XSS, а шифровать его бессмысленно, потому что ключ хранится в том же origin. Данные живут только в форме, а запоминание доверено браузеру через `autocomplete="tel"` и `autocomplete="street-address"`.
- **Корзина в localStorage как внешние данные.** В хранилище пишется версия формата, при чтении каждая позиция проверяется, битые отбрасываются. Ключ содержит id магазина. Корзина синхронизируется между вкладками через событие `storage`. Хранилище передаётся в стор как зависимость, поэтому тесты работают с корзиной в памяти.
- **Заказ не повторяется автоматически.** POST не идемпотентен, повтор может создать дубль. При ошибке корзина и заполненная форма сохраняются, и покупатель повторяет отправку сам.
- **Устаревшие данные после неудачного запроса.** Когда повторный запрос падает, RTK оставляет в `data` предыдущий успешный ответ. Поэтому при сверке сначала проверяется статус запроса, а не `data`, иначе старая цена сошла бы за свежую. Эту ошибку поймал тест.
- **Форма ответа бэкенда не выходит за пределы `api/`.** Мапперы переводят DTO в доменные типы: `category` становится `categoryId`, массив `images` — одной картинкой или `null`. Если сменится бэкенд, поменяется только адаптер.
- **Состояние — Redux Toolkit + Thunk (вариант 3 из задания).** Данные с сервера загружаются через RTK Query, который построен на `createAsyncThunk`. Отмена устаревших запросов, кэш и повтор получаются стандартными средствами.
- **Каталог — infinite query.** Номер страницы — это `offset`, а «Загрузить ещё» — это `hasNextPage`. Кэш хранится отдельно для каждого сочетания категории и поиска, поэтому смена фильтра всегда даёт новый запрос, а поздний ответ по старой категории не перезапишет новую. `keepUnusedDataFor: 0` выбрасывает страницы покинутой категории.
- **Автоповтор по политике.** GET повторяется с экспоненциальной задержкой только при сбоях сети и ответах 5xx. 404 не повторяется, запись (заказ) не повторяется никогда. Политика — чистая функция `shouldRetry` с тестами. Когда возвращается сеть, запросы перезапускаются сами.
- **Ошибки внутри виджета.** У каждого блока свой лоадер и своя ошибка с кнопкой «Повторить», перезагрузка страницы не нужна. Если упала догрузка, уже показанные товары остаются, а повторяется только следующая порция.
- **Нет сети — плашка и автоповтор.** Статус сети читается через `useSyncExternalStore` из событий `online`/`offline`. Когда сеть возвращается, RTK Query сам перезапрашивает упавшие данные (`refetchOnReconnect`), нажимать ничего не нужно. В RTK подписка на эти события глобальная на модуль, поэтому у стора есть `dispose()`: без него в тестах каждый следующий стор оставался бы без неё.
- **Старый список не выдаёт себя за новый.** При смене категории или поиска каталог берёт `currentData`, а не `data`: в `data` RTK держит ответ по прошлому фильтру, пока новый грузится или если он упал. Иначе вместо лоадера или ошибки на экране оставался бы старый список. Баг нашёлся при проверке в браузере, теперь его закрывают два теста.
- **Ленивые страницы и отдельный чанк библиотек.** Страницы товара и корзины грузятся при первом переходе (`React.lazy`), лоадер показывается внутри layout. Библиотеки собраны в отдельный `vendor`-чанк: они меняются реже кода приложения, и после деплоя браузер берёт их из кэша.
- **Холодный старт Render.** Если ответа нет дольше 8 секунд, под лоадером появляется пояснение: бесплатный бэкенд просыпается до минуты. Короткий таймаут здесь только оборвал бы рабочий запрос.
- **Фильтр каталога в URL.** `?q=` и `?category=` переживают перезагрузку и кнопку «Назад». При смене категории поиск сохраняется. Невалидная категория в адресе превращается во «Все» и не ломает страницу.
- **Картинки разных пропорций.** Фото приходят с соотношением сторон от 0.56 до 2.1. Рамку задаёт `aspect-ratio` из конфигурации бренда, фото вписывается целиком через `object-fit: contain`. Битая ссылка заменяется заглушкой, карточки в ряду одной высоты.
- **Пустой результат поиска.** Показывается «ничего не найдено», подсказка о том, как работает поиск, и кнопка сброса. Пустая категория и пустой поиск различаются.
- **Тесты с MSW.** Моки повторяют логику бэкенда (категория, поиск по названию и цвету, offset), и тесты проверяют, какие именно запросы ушли на сервер.
- **В `index.html` нет брендовых строк.** Название, описание и favicon выставляет React 19 через `<title>`, `<meta>` и `<link>`. В самом `index.html` стоит только пустая иконка-заглушка: без неё браузер, пока грузится скрипт, запрашивает `/favicon.ico` с корня домена и затем отменяет запрос.
- **Base сборки из имени репозитория.** Относительный `base: './'` здесь не работает: на вложенных URL вроде `/catalog/20.html` ломаются пути к ассетам. Поэтому workflow передаёт `--base=/<репозиторий>/`, а роутер берёт `basename` из `import.meta.env.BASE_URL`.
- **SPA на GitHub Pages.** Pages не умеет перенаправлять все пути на одну страницу, поэтому плагин сборки (`build/staticPages.ts`) кладёт копии `index.html` под именами страниц из `ROUTES` (`catalog.html`, `about.html` и т. д.): прямой заход и перезагрузка отвечают 200, а не 404. Страницы товаров `/catalog/:id.html` динамические, их открывает запасной `404.html` с тем же приложением.
- **`/catalog/:id.html`.** React Router 8 сопоставляет параметр с суффиксом, но пропускает и `abc.html`. `parseProductId` отсекает нечисловые id до запроса, и показывается 404.
- **Поиск через URL.** Шапка ведёт на `/catalog.html?q=…`. Запрос переживает перезагрузку и кнопку «Назад», каталог читает его из адреса.
- **Ошибки рендера не ломают страницу целиком.** `errorElement` висит на беспутевом маршруте внутри `MainLayout`, поэтому шапка и футер остаются на месте.
- **Иконки шапки — `button` и `Link` вместо `div`.** Они доступны с клавиатуры и понятны скринридеру. Корзина открывается в новой вкладке средним кликом.
- **Bootstrap 4.6.2 из npm.** CDN StackPath из вёрстки закрыт, а Bootstrap 5 не подходит: в нём удалены `mr-auto` и `form-inline`. Font Awesome подключался, но нигде не использовался, поэтому убран.

## Стек

React 19.3, React Router 8.4, Redux Toolkit 2.12 (RTK Query), TypeScript 6.0, Vite 8.3, Bootstrap 4.6, Vitest 5 + Testing Library + MSW, ESLint 9 (typescript-eslint, react, react-hooks, jsx-a11y) + Prettier, GitHub Actions → GitHub Pages.

ESLint остаётся на 9-й версии, потому что `eslint-plugin-react` и `eslint-plugin-jsx-a11y` не поддерживают 10-ю. TypeScript остаётся на 6.0, потому что `typescript-eslint` требует `<6.1`.
